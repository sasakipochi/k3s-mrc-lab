見どころ

  1. 「MRC で開始」→ 8 経路にほぼ均等にばら撒かれる。受信側では順番の入れ替わりが大量に起きるが、届いた順にそのまま受け取るので問題にならない
  2. 「uSID トレース」→ スイッチを 1 台通るたびに宛先アドレスが 16 bit ずつ左にずれていく (経路はパケットの宛先に全部書いてある)
  3. 経路を選んで「150%」で混雑させる → そのリンクでトリミングされたヘッダーだけが先に届き、受信側が NACK → 別の経路で即再送。その経路は避けられて、他の経路の流量は変わらない
  4. リンクを「切断」→ ACK が返らずタイムアウトした経路だけ故障扱いになり、残りの経路で走り続ける。「復旧」するとプローブが通って使用再開。スイッチには何も設定していない (経路の切り替えは送信側だけ)
  5. 「従来方式で開始」して同じことをする → 1 経路ぶんしか速度が出ない。混雑や切断に当たると go-back-N でまとめて送り直し、切断では 3 秒 (ルーティング収束の模擬) 止まる
  6. 「トリミング無効」で混雑させる → ヘッダーも捨てられるので、タイムアウトを待ってからの再送になり、混雑しただけの経路を故障と区別できない
